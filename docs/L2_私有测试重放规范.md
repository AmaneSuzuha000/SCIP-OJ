# L2 私有测试重放规范（草稿，待课程正式启用验收）

## 目标与安全边界

此前 L2 评测每次使用 `secrets.randbits(64)` 生成临时私有实例，能够隐藏题目，却无法在成绩申诉或复判时恢复原测试。新的协议 `hmac_sha256_submission_v1` 对**同一份不可变提交**生成相同测试种子；不同提交仍使用不同的私有实例。

```text
seed_i = first_64_bits(
    HMAC_SHA256(server_secret,
      "scip-oj:l2:hmac_sha256_submission_v1:{problem_id}:{submission_id}:{i}")
)
```

- HMAC 密钥只留在 GitHub Actions 可信宿主机，不注入学生 Docker 容器，也不能写入前端、成绩报告或 Git 提交。
- 正式工作流优先读取 `GRADE_PRIVATE_TEST_KEY` Secret；迁移期可回退到既有 `GRADE_CALLBACK_SECRET`（采用不同用途的 HMAC 输入域分隔）。
- 如果运行环境缺失私有测试密钥或提交 ID，正式评测必须返回 `system_error`（`score=null`），不能把缺配置当学生 0 分。
- 本地独立运行若未设置重放环境，仍使用临时随机实例，报告明确标注 `ephemeral_random`，不得作为可重放正式成绩。
- 评测报告记 `seed_protocol` 和 `judge_commit`；不记录明文密钥或原始私有种子。

## 复判条件

要重现当次测试，必须同时保留：

1. 原 `submission_id`、题目 ID 和 `n_instances`。
2. 原 HMAC 密钥及其密钥版本。密钥轮换前应有正式的历史密钥留存与授权复判机制。
3. 原判题源码版本（报告 `judge_commit`）和原实例生成器版本。
4. 原 PySCIPOpt/SCIP 容器镜像摘要及相关评分配置。

**目前只完成测试实例生成的确定化与源码 commit 留痕，未达成整个评测环境的完全冻结。** 题目配置快照、Docker 镜像 digest、历史密钥版本和持久队列恢复仍是后续验收门槛，不得因此宣称已经实现完整法证重放。

## CI 验收

- 对同一 `problem_id + submission_id + index + secret` 生成的测试完全一致；
- 更改任一字段产生不同伪随机实例；
- HMAC 密钥不透传至容器；
- 生产缺密钥返回系统错误而非 0 分；
- 现有 P001/P002 Docker 隔离评分和 Notebook 独立 oracle 回归通过。

## 教学部署

先在独立分支通过 CI；在预生产环境使用测试账号对同一提交进行两轮重判，核对测试实例逐项一致。完成教师/学生真实账号 E2E 后，再评估上线。此文档并不授权直接修改生产成绩数据。
