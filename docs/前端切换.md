# 前端切换（React 新壳）

新前端在 `web/`，与旧 `site/` 并行存在。切换是一个仓库变量，回滚就是删掉它。

## 切换

在 GitHub 仓库设置里添加 Actions 变量：

    WEB_SHELL = react

之后 `deploy.yml` 会先用 Vite 构建 `web/dist`，再交给 `scripts/assemble_site.py --web-dist`。
把变量删掉（或改成任何其他值）即刻回到旧壳。

## 两种壳的共同点

无论用哪套壳，下面的内容都由同一个装配脚本搬运，不经过前端代码：

- `notebooks/`：JupyterLite 构建 + `engine.js` / `bridge.js`，建模课运行时
- `problems/`、`docs/`：题库与公开文档
- `assets/katex/`：公式渲染
- `lab/`、`repl/`：旧链接的跳转壳，保证书签不失效

新壳额外携带 `404.html`。GitHub Pages 没有 SPA 回退，缺少它时直接访问
`/course/<uuid>` 会 404，因此装配脚本会在缺失时直接报错退出，而不是部署一个坏站点。

## 本地验证

    npm --prefix web ci
    npm --prefix web run build
    # 干跑：把新壳装配到一个临时目录，不发布
    PYTHONUTF8=1 python scripts/assemble_site.py --lite lite-build --web-dist web/dist --output dist-web
    PYTHONUTF8=1 python -m unittest discover -s tests -p "test_assemble_web.py"

装配逻辑只有 `scripts/assemble_site.py` 一处实现，本地验证与线上部署走同一条代码路径。

## 回滚

清空 `WEB_SHELL` 后重新运行 Deploy GitHub Pages。旧壳与旧构建产物从未被删除，
`site/`、`.portal-build` 仍在仓库里。

## 尚未迁移的部分

- 教师端目前是只读下钻（课程 → 作业 → 提交），发布作业、批量复判仍是旧站功能
- 建模课的交互式 notebook 仍通过 iframe 嵌入，未重写
- 旧站的 18 个 script 标签与 CodeMirror 5 只在新壳完全接管后才可删除

删除 `site/` 属于最后一步，必须在新壳线上稳定之后单独提交。
