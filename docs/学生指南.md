# 学生指南：SCIP-OJ 使用说明

欢迎使用 SCIP-OJ 系统建模与优化平台！本平台提供「**本地免配置练习**」与「**网页端一键提交正式作业**」双轨功能。

---

## 模式一：L1 浏览器练习（不作正式成绩）

1. **进入题目**：打开站点首页题单，点击对应题目（如 `P001 0-1背包问题`）。
2. **理解契约**：阅读题面中的输入输出格式定义，确保编写的函数签名满足：
   ```python
   def solve(instance: dict) -> dict:
       ...
       return {
           "status": "optimal",
           "objective": float(...),
           "solution": {...}
       }
   ```
3. **点击「⚡ L1 练习评分（浏览器 WASM）」**：
   - 浏览器将通过 WebAssembly (WASM) 在你的设备本地直接运行 Python 代码。
   - 对预置的多组随机实例进行求解与性质校验（可行性、整数性、目标 gap）。
   - 取多实例的**算术平均分**；平均分 ≥ **90 分**即提示通过。
   - **首次加载提示**：首次点击时浏览器需下载约 6MB 的 WASM 运行环境，初次初始化耗时数秒，后续运行为秒级响应。
4. **注意**：L1 评测仅作为学生编写代码时的即时自测反馈，保存在本地浏览器缓存中，**不作为课程正式成绩**。

---

## 模式二：JupyterLab (PySCIPOpt) 交互式建模

如果题目涉及复杂的整数规划、混合整数规划（MIP）或需要调用 SCIP 求解器：
1. 点击页面顶部导航栏的 **「JupyterLab (PySCIPOpt)」**。
2. 浏览器将打开基于 WebAssembly 构建的在线 JupyterLite 实验环境（已预装 `xeus-python`、`pyscipopt` 和 `numpy`）。
3. 学生无需在个人电脑上安装编译 SCIP，即可直接在 Notebook 中交互运行：
   ```python
   from pyscipopt import Model

   model = Model("example")
   x = model.addVar(vtype="B", name="x")
   # 自由定义约束与目标...
   model.optimize()
   ```
4. 左侧文件树中提供了 `content/01_P001_knapsack_PySCIPOpt.ipynb` 等示例建模教程供参考。
5. 在 JupyterLab 中调试通过后，将最终的 `solve(instance)` 函数复制回力扣壳代码框中。

## 模式三：正式作业提交（网页端一键提交）

正式课程作业**直接在网页端提交并出分**，你**不需要**注册 GitHub 账号，也**不需要** Fork 仓库或开 Pull Request。

### 1. 账号登录
- 点击页面右上角的 **「登录 / 注册」** 按钮。
- 若首次使用，切换至 **「学生账号注册」** 标签，输入你的**真实姓名**、**学号**（如 `20260001`）、邮箱与密码完成注册。
- 登录后右上角会显示你的姓名与学号（如 `👤 李同学 (20260001)`）。

### 2. 查阅作业要求
- 进入作业题目后，代码框上方会显示作业元信息条：
  - **截止时间**：在此时间前提交的有效成绩计入最终成绩。
  - **及格线**：通常为 90 分。
  - **计分规则**：默认为「截止前最高分」。

### 3. 点击「🚀 提交正式作业（服务端评测）」
- 点击按钮后，平台将把代码安全发送给评测服务端。
- 服务端会自动调度 Linux 权威评测环境（搭载完整 PySCIPOpt 优化求解器内核），对你的代码进行独立的随机实例测试。
- 状态栏将提示：`✅ 提交成功！公开编号 SUB-XXXXXXXX，已进入服务端评测队列。`

### 4. 查看「我的提交记录」与分数
- 页面下方的 **「📜 我的提交记录（正式作业）」** 列表会显示你的所有历史提交记录：
  - **评测状态**：
    - `⏳ 排队中` (queued)：任务正在等待 runner 调度。
    - `⚙️ 评测中` (running)：runner 正在执行求解与性质验证。
    - `已完成` (done)：已出分（如 `90 分` 或 `100 分`）。
    - `⚠️ 系统故障` (system_error)：如遇到 runner 环境或服务崩溃，状态将显示为系统故障。**系统故障绝不计为学生 0 分**，分数为未出分状态，可点击刷新重试或联系助教。
  - **查看详情**：点击操作列的「查看详情」，可展开查看服务端的详细判定输出与每个测例的反馈。

### 5. 多次提交与计分策略
- 允许在作业截止前多次提交。
- 每次提交均会生成一条独立的记录并保留历史代码，系统默认取**截止时间前的历史最高分**作为该题的最终课程成绩。

## （可选备用）开发者 PR 提交通道

若你参与题目开发或助教本地测试，仓库仍保留了传统的 GitHub Pull Request 自动测试流水线：
1. Fork 仓库并在本地新建分支。
2. 放入文件：`submissions/<github_user>/<problem_id>.py`。
3. 提交 PR 至 `main` 分支，GitHub Actions 机器人将在 PR 下回复 L2 评测报告。
