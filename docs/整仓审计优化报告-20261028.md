**SCIP-OJ 核心平台已具备正式开课评测的健壮基础架构**：

## 4. 关键模块实测与代码深度审计

### 4.1 架构与构建 (`scripts/assemble_site.py`, `build_portal.mjs`, `deploy.yml`)
- **构建输出与源文件分离**：源码位于 `site/src/`，构建产物输出到 `.portal-build/js/`，`assemble_site.py` 严格校验输入产物完整性，禁止源目录与输出目录发生混淆冲突，符合设计契约；
- **静态站密钥安全**：`deploy.yml` 仅将 `SUPABASE_URL` 与 `SUPABASE_ANON_KEY` 写入 `dist/config.js`；经全局搜索排查，代码中没有任何 `service_role` 密钥、GitHub Token 或 HMAC 密钥泄露到前端资源中。

### 4.2 学生端 (`site/src/student/**`)
- **练习评分与正式提交严格分流**：
  - **L1 练习自测**：通过 `site/js/python_runtime.js` 在浏览器本地 Pyodide/xeus-python WASM 沙箱中执行，使用公开样例算例，执行结果仅存入 `localStorage` 作为做题进度缓存，**绝不写入 Supabase 正式表**；
  - **正式提交**：必须经过学号门禁（非教师且未填学号时强制弹窗拦截）与选课门禁，通过 `submitAssignment` Edge Function 走数据库事务入队；
- **考试诚信模式 (`site/js/exam-integrity.js`)**：
  - 属于**客户端威慑与自报指标**，明确标注“浏览器自报计数，不可作为绝对作弊证据”；
  - 考试模式下自动停用 `localStorage` 本地草稿，防止公用机房遗留代码。

### 4.3 教师端 (`site/src/teacher/**`)
- **成绩簿与试交标记**：
  - 正确消费 `course_gradebook` 视图与 `get_teacher_gradebook` RPC；
  - 教师与助教在平台上的烟测提交会被打上 `<span class="tag-pending">试交</span>` 徽标，并在统计中独立分离，不污染全班及格率；
- **证据台 (`evidence.js`)**：
  - 展示提交代码、评测 JSON 报告及流水时间线；
  - 所有动态文本使用 `esc()` 转义或赋值给 `textContent`，杜绝了 XSS 漏洞；
- **CSV 导出防御**：
  - 导出成绩 CSV 时，对 `[=+\-@\t\r]` 开头的单元格强制添加 `'` 单引号前缀，彻底防御了针对 Excel 的 CSV 公式注入攻击（CSV Injection）。

### 4.4 平台层与状态 (`site/src/platform/**`, `grading-api.js`, `grading-state.js`)
- **成绩语义规范化 (`grading-state.js`)**：
  - 正确区分 `latestAttempt`（最近一次评测，无论成功与否）与 `effectiveGrade`（有效成绩，必须为状态为 `done` 且出分合法的评测）；
  - 教师复判即使下调了分数，也会在成绩表中生成新的 attempt 并正确覆盖旧有效分，解决了“低分复判不生效”的业界常见顽疾；
- **请求键幂等机制 (`request-keys.js`)**：
  - 基于 Web Crypto SHA-256 派发客户端 UUID 请求键，应对弱网响应丢失后的刷新重试。

### 4.5 Supabase 数据库与 RLS (`supabase/migrations/**`)
- **原子性入队与配额限制 (`010_submission_atomic_quota.sql` & `reliable_grading_lifecycle.sql`)**：
  - 在 `enqueue_grading` 内获取行级锁与 `pg_advisory_xact_lock`，杜绝并发竞争重放；
  - 限制 20 秒冷却期、每小时同题上限 12 次、单日全站上限 60 次；
  - 教师复判仅追加 grading 记录，不扣除学生提交限额；
- **默认权限边界 (`011`, `014`)**：
  - `011` 彻底 REVOKE 了 public 表的 TRUNCATE/TRIGGER/REFERENCES 权限；
  - `014` 对 `postgres` 角色的默认 ACL 进行收紧，新表默认不赋予 `anon` 和 `authenticated` 权限。

### 4.6 判题与沙箱隔离 (`judge/**`)
- **Docker 运行时边界 (`judge/sandbox.py`)**：
  ```python
  docker_args = [
      "docker", "run", "--rm", "-i",
      "--network", "none", "--read-only", "--ipc", "none",
      "--cap-drop", "ALL", "--security-opt", "no-new-privileges",
      "--pids-limit", "64", "--memory", "768m", "--memory-swap", "768m",
      "--cpus", "1", "--user", "65534:65534",
      "--tmpfs", "/tmp:rw,nosuid,noexec,size=64m",
      "--cidfile", str(cidfile), ...
  ]
  ```
  实现了极高等级的安全隔离容器。执行过程无网络连接，根目录只读，丢弃所有特权，单核受限。
- **评测协议隔离**：
  - 宿主执行的 `runner_l2_isolated.py` 绝不使用 `importlib` 动态导入学生代码，全部通过 stdin/stdout 与隔离容器中的 `sandbox_worker.py` 进行 JSON 通信；
  - 私有算例在宿主侧生成后将 `optimal_value` 剥离，再行传入容器。

### 4.7 持续集成与任务恢复 (`.github/workflows/**`)
- **自动恢复与漏单巡检 (`recover-gradings.yml`)**：
  - 每 5 分钟定时触发一次，调用 `recover_grading_jobs` 与 `lease_grading_dispatches`；
  - 对 20 分钟未回传的僵尸任务判定为 `system_error`，并在最大深度内自动派发重试（retry_depth < 2）；
- **回调签名验证**：
  - Actions Runner 评测完成后，使用 `GRADE_CALLBACK_SECRET` 通过 HMAC-SHA256 对报告内容进行签名，回调 Edge Function 进行常量时间比对验签入库。

### 6.1 性能优化研究
1. **成绩簿 RPC 与大并发查询优化**：
   - 当前 `course_gradebook` 视图采用 `CROSS JOIN assignments a` 与 `ROW_NUMBER() OVER (...)` 窗口函数；
   - 在班级人数 < 100、题目 < 10 时查询在 30ms 内完成；若选课人数达到 200+ 人，建议在 `get_teacher_gradebook` RPC 中增加针对指定 `problem_id` 的可选入参过滤，避免无条件全量扫描计算；
2. **学生端智能轮询频率与退避策略**：
   - 目前学生端排队轮询间隔为固定的 3 秒（最多 30 次）；
   - 建议改造为指数退避（例如前 3 次 2s，随后 4s、8s），并在达到 30 次后停止并显示温和的手动刷新提示，显著减少 Supabase REST API 的并发请求量。

### 6.2 可观测性体系研究
1. **评测执行环境不可篡改指纹留存**：
   - 当前沙箱虽然检查并记录了 Docker Image ID，但镜像构建未固定 Digest；
   - 建议在 GitHub Actions 构建镜像后将 `scip-oj-student@sha256:...` 写入 `gradings.config_snapshot` 的 `image_digest` 字段中，为学术申诉提供绝对可复现依据；
2. **任务出库流转状态跟踪**：
   - 建议在教师端证据台增加“调度详情”卡片，展示当前 grading 的 `retry_depth`、`dispatched_at` 及 `lease_token` 状态，便于在出现外部服务故障时快速定位是 GitHub Actions 调度延迟还是 Runner 排队。

### 6.3 可维护性与代码健康度
1. **前端样式工程化**：
   - 当前 CSS 文件达 10 余个，部分通过 `@import` 级联；
   - 建议在随后的阶段中，引入统一的 CSS 打包（或使用 esbuild 处理 CSS 入口），消除运行时额外的 HTTP 探测，提升首屏渲染性能；
2. **测试环境标准化**：
   - 将 Playwright 依赖声明收敛，为本地开发者提供无侵入式的快照测试脚本，使本地与 CI 环境对 UI 测试的执行能力完全对齐。

### 6.4 课程运营与诚信策略
1. **考试模式分级配置指南**：
   - `standard`（日常作业）：允许粘贴、允许本地草稿保存，无多余提醒；
   - `exam_warn`（平时测验）：允许粘贴，但记录事件频次并提示学生，供课后教师核验；
   - `exam_block`（期末闭卷）：强制拦截剪贴板与拖放操作，强制要求学生先经线下教师核验（`roster_verifications` 门禁）。
2. **离线防作弊审查产品化**：
   - `scripts/audit_similarity.py` 表现稳定（Token 7-gram + Jaccard 相似度），建议未来在教师控制台增设“导出本题相似度候选对”的一键触发按钮，教师无需登录服务器即可下载审查清单。
