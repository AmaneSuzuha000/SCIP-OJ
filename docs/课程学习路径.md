# 课程学习路径

这条路径把建模概念、站内 Notebook 和已有 OJ 题目按学习顺序串起来。可以按三课往下读，也可以从某一课的 Notebook 直接动手。

打开这些页面前，需要使用已获授权的 GitHub 账号登录。白名单只决定能否进入站点，不改变题目怎么计分。浏览器里的 Notebook 和「练习评分」用来检查模型，**不计入正式成绩**。正式成绩只来自「课程教学」里的正式提交。

## 建议节奏

| 模块 | 在学什么 | 建议学时 | 从这里进入 |

| 第 1 课 建模与 SCIP | 变量、约束、目标；线性规划与整数规划；分支定界在剪什么 | 2 学时，外加把背包题跑通 | [课文](doc.html?path=docs/lessons/01-建模与SCIP入门.md) |
| 第 2 课 经典组合优化 | 运输、下料、装箱、指派、设施选址 | 3 学时 | [课文](doc.html?path=docs/lessons/02-经典组合优化应用.md) |

学时是课堂阅读加一次改数据的练习，不是考勤。某一课卡住时，留在对应 Notebook 里改一个数，看方案怎么变。

## 练习和正式提交

- **练习**：课程实验中的背包、指派 Notebook，拓展学习里的建模 Notebook，以及题目页的「练习评分」。结果留在这台浏览器里。
- **正式提交**：登录并加入班级后，从「课程作业」提交。目前能进入正式评测的，是已经有判分协议的题目（P001 背包、P002 指派，以及教师另行发布的仿真题）。本路径新加的运输、下料、巡检、配送、单机 Notebook **不会**自动写入成绩簿。
- 教师把某题发布成作业之后，以该作业页面上的截止时间和及格线为准。

## 这一轮先不展开

下面三件事在课文里会点到名字，没有单独的 Notebook：

- **广义指派**：一台机器或一名工人可以接多件任务，但有容量。普通指派是它在容量刚好够「一人一件」时的特例。
- **带时间窗的车辆路径**：在带容量配送上再要求每个点的到达时刻落在窗口内。
- **并行机调度**：多台机器同时加工，决策变成「分给哪台机器、在那台上排第几」。
