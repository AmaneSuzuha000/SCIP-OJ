# 出题指南（老师）

面向「文件出题」：不改站台代码也能加题。判分政策见 [判分协议-已冻结.md](./判分协议-已冻结.md)。

## 1. 目录约定

在 `problems/` 下新建 `P00x_slug/`，至少包含：

| 文件 | 作用 |
|------|------|
| `README.md` | 题面（中文） |
| `meta.json` | 判分参数 |
| `template.py` | 学生起点；必须有 `solve(instance) -> dict` |
| `gen.py` | `generate(seed) -> instance`（可委托 `judge.runner_l1`） |
| `judge.py` | `grade(result, instance, meta)`（通常委托 `judge.common`） |

然后在 `problems/index.json` 增加一条题单记录。

## 2. `meta.json` 必填字段

参考 P001 / P002：

- `id`：如 `"P002"`
- `sense`：`"maximize"` / `"minimize"`
- `eps_feas` / `eps_int` / `eps_obj`
- `time_limit_sec`
- `pass_score`：默认 **90**
- `n_instances_l1`：默认 **3**（多实例**算术平均**）
- `seed_base`：实例种子起点
- `weights`：`F/C/I/O` 分项权重（和为 90+ 即可）
- `grader`：浏览器与 Python 共用的判分器名（如 `knapsack`、`assignment`）

## 3. 实例与返回契约

`instance` 必须自带 `optimal_value`（由 `gen` 用确定性算法算出），供目标 gap 评分。
学生 `solve` 返回：

```python
{"status": "...", "objective": float, "solution": ...}
```

判分顺序：**格式 → 可行性 → 整数性 → objective 与解一致 → 目标 gap**。不要只比对打印字符串。

## 4. 浏览器练习评分器

若该题要在 Pages 上点「练习评分」：

1. 在 `site/src/student/` 增加练习评分器，输入结构与评分规则应与 Python 评分器一致。公开练习实例不复用服务端私有测例。
2. 在 `site/src/student/practice.js` 注册该 `meta.grader` 的样例生成与评分入口。
3. 添加浏览器与 Python 的交叉验证，然后执行 `npm test`。
4. 浏览器端通过已准备好的 Python / PySCIPOpt 环境真实执行代码，练习不写正式成绩。

## 5. 正式成绩与平台评测

平台现已支持**全链路网页端作业提交与自动评测**：

1. **题目录入与作业发布**：
   - 通过教师控制台发布题目，设置班级、截止时间、及格线、实例数和计分规则。
   - 默认采用 `highest_before_due`（截止前最高分）计分规则。
2. **自动化评测流水线**：
   - 学生在网页端点击「提交正式作业」后，由 `submit-assignment` 校验身份和权限，并在事务内保存源码快照、评测任务和派发记录。任务随后派发到 `.github/workflows/grade-submission.yml`。
   - Runner 检出冻结的判题版本，由 `judge/runner_l2_isolated.py` 在无网络 Docker 容器中执行学生代码；可信宿主验证结果，HMAC-SHA256 回调原子完成评分。学生源码不在宿主 Python 进程导入。
   - 教师可在 `site/teacher.html` 实时查阅班级成绩簿，并支持导出 UTF-8 CSV。
3. **出题规范**：
   - 保证 **Python `judge` 验证逻辑不依赖 SCIP 求解器**（由 `gen.py` 用确定性算法算出 `optimal_value`，`judge.py` 仅比对可行性、整数性与目标值 gap）。
   - 评测 runner 预装完整 `PySCIPOpt`，学生代码可自由调用 `from pyscipopt import Model` 建模。
