## 一、阶段 2 目标与双轨架构演进

在阶段 1 实现「本地 WASM 练习」与「权威服务端判卷 + 成绩中心」的基础上，阶段 2 全面解决了课堂真实开课与运营的最后短板：

### 核心安全硬边界

1. **正式成绩只来自服务端**：浏览器内的 WebAssembly 练习或 localStorage 仅作为学生个人即时调试，**绝不能写回正式数据库成绩**。
2. **纯 GitHub OAuth 身份认证**：停用旧邮箱/密码注册，全站统一使用 GitHub OAuth 登录；学生**不需要**学习 Git、不需要 Fork 仓库或提 PR，GitHub 仅作为可靠身份。
3. **前端密钥绝对隔离**：`site/` 前端代码仅注入公开的 `SUPABASE_ANON_KEY`；`SUPABASE_SERVICE_ROLE_KEY`、GitHub PAT、HMAC 密钥**严禁**进入前端。
4. **系统异常与学生 0 分物理隔离**：评测 runner 依赖缺失或异常时，状态标记为 `system_error`，`score` 必须保留为 `NULL`，**绝不能判定学生为 0 分**。
5. **不可变审计与复判追溯**：学生代码一旦提交触发哈希计算并锁定；教师单条或批量复判均完整记录修改前分数、操作人与原因至 `grade_audits`。

## 二、数据库结构演进 (004 Migration)

迁移脚本位于 `supabase/migrations/004_course_invites_roster_assignments.sql`：

### 1. 课程邀请码 (`course_invites` & `courses.invite_code`)
- `courses.invite_code`：邀请码短号（如 `SCIP2026-FALL`）。**注意：006 迁移后该列不再对所有登录用户可读**，仅本课程教师可通过 `get_course_invite_code(course_id)` RPC 读取，避免邀请码被任意登录用户列出。
- `course_invites` 表：
  - `id` (UUID), `course_id` (UUID), `code` (TEXT UNIQUE)
  - `role` (TEXT, 默认 `student`)
  - `expires_at` (TIMESTAMPTZ, 可选有效期)
  - `max_uses` (INTEGER, 可选名额上限)
  - `uses_count` (INTEGER, 已使用次数)

### 2. 待匹配花名册 (`roster_pending`)
- 存储教师通过 CSV 预先导入的班级名单：
  - `course_id` (UUID), `student_no` (TEXT), `display_name` (TEXT)
  - `github_login` (TEXT, 可选)
  - `status` (`pending` / `matched`)
  - `matched_user_id` (UUID, 学生登录认领后关联)
- **触发器联动**：当学生在 `profiles` 中首次录入或更新学号时，触发器 `trg_profile_student_no_sync` 自动将状态设为 `matched`，实现教务花名册与 GitHub 账号的无缝对齐。

### 3. 作业配置增强 (`assignments`)
- 支持动态定义作业考核规则：
  - `problem_id` (P001, P002...)
  - `due_at` (截止时间，允许留空长期有效)
  - `pass_score` (及格线，默认 90 分)
  - `n_instances` (服务端测试实例数，默认 3)
  - `score_policy` (`highest_before_due` / `latest` / `highest`)

### 4. 行级安全策略 (RLS) 演进
- `course_invites`：允许认证用户查询，教师拥有全生命周期管理权限。
- `roster_pending`：基于 `is_teacher_of(course_id)` 严格限制仅任课教师可查阅与导入。
- `assignments`：授予任课教师 `INSERT` 与 `UPDATE` 权限。
- `profiles`：允许用户随时更新个人学号与显示姓名。

## 三、Edge Functions 接口规范

所有 Edge Functions 源码位于 `supabase/functions/`，统一具备完整的 CORS 处理与安全鉴权：

| 函数目录 | 请求方式 | 鉴权要求 | 核心功能 |
|---|---|---|---|
| `submit-assignment` | POST | 学生/教师 JWT | 校验选课资格、检查截止时间标记 `late`、计算 SHA-256、创建提交与排队评测并调度 Actions |
| `grade-callback` | POST | HMAC-SHA256 签名 | 验证 GitHub Actions 评测回调请求并更新分数、报告与通过状态 |
| `regrade` | POST | 教师 JWT | 发起单条提交重新评测，记录旧分至审计表 |
| `regrade-batch` | POST | 教师 JWT | 批量复判勾选项，或通过 `{course_id, problem_id}` 发起整题一键重判 |
| `publish-assignment` | POST | 教师 JWT | 教师在网页端发布或调整课程作业（免写 SQL） |
| `join-course` | POST | 学生 JWT | 校验邀请码有效性、有效期与名额上限，写入选课表并对齐花名册 |

## 四、教师控制台 (site/teacher.html) 功能详解

教师控制台包含三大核心模块：

### 1. 班级成绩表与评测证据台
- **班级总表**：按学号、姓名、题目展示最优成绩、通过判定、迟交状态（正常/迟交）、提交次数与最后提交时间。
- **组合检索**：按特定题目快速筛选，或按学号/姓名关键词搜索。
- **评测证据台**：
  - **代码只读查看器**：直接查看学生提交至 GitHub Actions 运行的不可变源码；
  - **结构化评测报告**：展示多实例得分、性质判定明细与求解器运行日志；
  - **状态时间流水线**：直观展示提交时间、调度时间与权威判定时间。
- **复判操作**：支持单条证据台复判、勾选多条批量复判与整题一键重判。
- **导出 CSV**：前端生成包含 UTF-8 BOM 头的 CSV 文件，在 Excel 中打开绝无乱码。

### 2. 花名册管理与导入
- 教师上传或粘贴 CSV（列格式：`学号,真实姓名,可选GitHub用户名`）。
- 实时展示预置总人数、已对齐人数与待绑定学生清单，便于未认领学生的跟进。

### 3. 作业发布与调整
- 表单化配置作业：选择题库题目、截止日期、及格分数、测试实例数与计分规则。
- 列表中展示当前课程已开放作业，支持一键回显修改。

## 五、学生端体验与门禁流程 (site/index.html)

1. **GitHub 登录**：顶栏一键授权，显示 GitHub 昵称。
2. **学号门禁**：若未填写学号，首次登录或点击提交时自动弹窗引导填写学号与姓名。
3. **选课门禁**：若未选修当前班级，弹窗引导输入邀请码（如 `SCIP2026-FALL`）。
4. **自主练习 vs 正式作业智能感知**：
   - 若题目已作为正式作业发布：展示作业元信息条与截止时间，提交按钮正常激活；
   - 若题目未作为正式作业发布：提示「自主练习模式」，正式提交置灰，L1 WASM 本地练习评分不受影响。
5. **智能轮询**：正式作业提交后前台自适应轮询评测进度，出分后自动停止。
6. **隐私脱敏课程排行榜**：点击「🏆 课程排行榜」可查阅当前题目的班级排行（学号自动脱敏为 `2026****01`）。

## 六、端到端自动化烟测

仓库提供两个独立且互补的自动化自测脚本：

```bash
# 1. 运行 Phase 1 评测引擎、系统错误隔离与 HMAC 烟测
./platform/scripts/smoke_phase1.sh

# 2. 运行 Phase 2 邀请码、花名册对齐、作业发布、迟交标记、批量重判与 CSV 烟测
./platform/scripts/smoke_phase2.sh
```

两个脚本均输出全绿色 `✓ PASS` 且退出码为 0，即表示系统功能状态完全健康。
