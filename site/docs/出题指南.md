# 出题指南（老师）

面向「文件出题」：不改站台代码也能加题。判分政策见 [判分协议-已冻结.md](./判分协议-已冻结.md)。

## 1. 目录约定

在 `problems/` 下新建 `P00x_slug/`，至少包含：

| 文件 | 作用 |
|------|------|
| `README.md` | 题面（中文） |
| `meta.json` | 判分参数 |
| `template.py` | 学生起点；必须有 `solve(instance) -> dict` |
| `gen.py` | `generate(seed) -> instance`（可委托 `judge.runner_l1`） |
| `judge.py` | `grade(result, instance, meta)`（通常委托 `judge.common`） |

然后在 `problems/index.json` 增加一条题单记录。

## 2. `meta.json` 必填字段

参考 P001 / P002：

- `id`：如 `"P002"`
- `sense`：`"maximize"` / `"minimize"`
- `eps_feas` / `eps_int` / `eps_obj`
- `time_limit_sec`
- `pass_score`：默认 **90**
- `n_instances_l1`：默认 **3**（多实例**算术平均**）
- `seed_base`：实例种子起点
- `weights`：`F/C/I/O` 分项权重（和为 90+ 即可）
- `grader`：浏览器与 Python 共用的判分器名（如 `knapsack`、`assignment`）

## 3. 实例与返回契约

`instance` 必须自带 `optimal_value`（由 `gen` 用确定性算法算出），供目标 gap 评分。  
学生 `solve` 返回：

```python
{"status": "...", "objective": float, "solution": ...}
```

判分顺序：**格式 → 可行性 → 整数性 → objective 与解一致 → 目标 gap**。不要只比对打印字符串。

## 4. L1（浏览器）镜像

若该题要在 Pages 上点「提交评分」：

1. 在 `site/js/` 增加与 Python 同规则的 `*_judge.js`（生成器种子算法必须一致）。
2. 在 `site/js/app.js` 按 `meta.grader` 分发。
3. `site/index.html` 引入脚本。

当前 MVP：**按钮跑内置最优 demo**，不执行 textarea 里的 Python（后续 JupyterLite/Pyodide）。

## 5. L2（正式成绩）

学生把代码放到 `submissions/<github_login>/<PROBLEM_ID>.py` 并发 PR。  
工作流 `.github/workflows/l2-grade.yml` 会：

- 加载同一套 `judge/` + 题目录
- 对多实例重判并在 **PR 评论**写分数摘要

出题时保证 **Python `judge` 不依赖 SCIP**（可用 DP/枚举算 `optimal_value`）；学生可用 SCIP，但 CI 用纯 Python 性质检查即可。

## 6. 合并前检查清单

- [ ] `index.json` 已登记  
- [ ] `meta.json` 字段齐全，`pass_score=90`，`n_instances_l1≥1`  
- [ ] 本地烟测：`python -c` 跑 `run_l1(load_solve(template), meta)` 能通过  
- [ ] 若上 L1 站：JS 种子与 Python `gen` 一致  
- [ ] README 写清 `solve` 契约与 `solution` 形状  
- [ ] 未把标准答案硬编码进前端唯一路径（性质验证 + 多 seed）
