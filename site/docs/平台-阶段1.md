# SCIP-OJ 平台阶段 1：成绩中心 + 自动化判卷架构与操作指南

本文档介绍 SCIP-OJ 平台在阶段 1 升级后的**全链路作业平台**架构、安全边界、配置方法及端到端验收流程。

---

## 一、架构摘要与双轨机制

SCIP-OJ 采用**双轨制**运行架构：

```
                ┌──────────────────────────────────────────────────┐
                │                 SCIP-OJ 前端 (site/)              │
                └───────┬──────────────────────────────────┬───────┘
                        │                                  │
          [练习轨: 浏览器本地]                  [正式作业轨: 服务端权威评测]
                        │                                  │
                        ▼                                  ▼
         ┌─────────────────────────────┐    ┌─────────────────────────────┐
         │ WebAssembly Python Runtime  │    │  Supabase Edge Functions   │
         │ (Pyodide / xeus-python)     │    │  (submit-assignment)        │
         └──────────────┬──────────────┘    └──────────────┬──────────────┘
                        │                                  │
                        ▼                                  ▼
         ┌─────────────────────────────┐    ┌─────────────────────────────┐
         │ 客户端性质验证判分 (L1)     │    │  PostgreSQL 数据库          │
         │ * 算术平均 / 及格线 90      │    │  * submissions (不可变)     │
         │ * 本地反馈，不记入正式分    │    │  * gradings (queued/done)   │
         └─────────────────────────────┘    └──────────────┬──────────────┘
                                                           │
                                                           ▼ (workflow_dispatch)
                                            ┌─────────────────────────────┐
                                            │ GitHub Actions Runner       │
                                            │ (.github/grade-submission)  │
                                            │ * 权威安装 PySCIPOpt        │
                                            │ * 多实例评分与性质检查      │
                                            └──────────────┬──────────────┘
                                                           │
                                                           ▼ (HMAC-SHA256 签名回调)
                                            ┌─────────────────────────────┐
                                            │ Supabase Edge Functions     │
                                            │ (grade-callback)            │
                                            └──────────────┬──────────────┘
                                                           │
                                                           ▼
                                            ┌─────────────────────────────┐
                                            │ 成绩中心 (course_gradebook) │
                                            │ * 教师面板 (site/teacher)   │
                                            │ * 截止前最高分聚合 / CSV导出 │
                                            └─────────────────────────────┘
```

### 核心安全与产品边界

1. **正式成绩只认服务端**：正式成绩由 GitHub Actions 权威 runner 评测后回写至 Supabase 数据库；浏览器的 L1 练习或 localStorage 仅用于本地快速调试，**绝不作为正式分来源**。
2. **学生无需 GitHub 账号**：学生只需在网页端注册学号与邮箱，直接点击「提交正式作业」即可，无需学习 Git/Fork/PR。
3. **密钥严格隔离**：
   - 前端（`site/`）：仅接触 `SUPABASE_ANON_KEY`（公开只读/行安全控制）。
   - **禁止** `SUPABASE_SERVICE_ROLE_KEY`、`GRADE_CALLBACK_SECRET` 或 `GITHUB_TOKEN` 进前端。
4. **系统故障与学生得分隔离**：
   - 若 runner 缺少求解器依赖或环境崩溃，评测状态置为 `system_error`，`score` 必须保留为 `NULL`，**绝不能判定学生为 0 分**。
5. **提交不可变性**：
   - 学生同一题目的多次提交产生独立的新 `submissions` 记录与递增的 `attempt_no`，数据库触发器禁止修改已插入的代码与哈希。

## 二、数据库结构与安全策略 (RLS)

SQL 迁移脚本位于 `supabase/migrations/`：

| 文件 | 说明 |
|------|------|
| `001_initial_schema.sql` | 核心表结构（`profiles`, `courses`, `enrollments`, `assignments`, `submissions`, `gradings`, `grade_audits`）及触发器 |
| `002_rls_policies.sql` | 行级安全策略（学生只读自己、教师读本课学生、service_role 独占评分写入权限、`is_teacher_of` 避免递归） |
| `003_views.sql` | `course_gradebook` 视图：按作业策略（默认 `highest_before_due`）聚合最优成绩、提交次数与提交 ID |
| `supabase/seed.sql` | 演示课程、P001/P002 作业定义、教师与学生测试账号初始化 |

### 关键表与字段

- `submissions`：
  - `id` (UUID), `public_code` (`SUB-XXXXXXXX` 格式短号)
  - `user_id`, `assignment_id`, `code_text`, `code_hash` (SHA-256)
  - `attempt_no` (同一学生对同作业递增计数)
  - `metadata` (记录迟交标识 `late: true` 等)
- `gradings`：
  - `submission_id`, `status` (`queued` / `running` / `done` / `system_error`)
  - `score` (0-100 或 NULL), `passed` (BOOLEAN), `report_json`, `error_message`, `runner_ref`
- `grade_audits`：
  - 记录教师在面板上点击「复判」的操作日志 (`grading_id`, `submission_id`, `actor_id`, `old_score`, `reason`)

## 三、部署与环境配置步骤

### 1. 创建并初始化 Supabase 项目

可以通过 [Supabase 官网](https://supabase.com) 免费创建项目，或者使用本地 CLI：

#### 选项 A：使用 Supabase Hosted 云端项目
1. 登录 Supabase 后台新建项目，记录：
   - Project URL：`https://<your-project-ref>.supabase.co`
   - API Keys：`anon public` 与 `service_role secret`
2. 打开后台 **SQL Editor**，按顺序执行：
   - `supabase/migrations/001_initial_schema.sql`
   - `supabase/migrations/002_rls_policies.sql`
   - `supabase/migrations/003_views.sql`
3. 在 **Authentication -> Users** 中创建测试教师和学生账号，并将 `supabase/seed.sql` 中的 UUID 替换为实际用户的 ID 后执行。

#### 选项 B：使用本地 Supabase CLI
```bash
# 启动本地开发服务（需安装 Docker 与 Supabase CLI）
supabase start

# 执行迁移与种子数据
supabase db reset
```

---

### 2. 部署 Edge Functions

三个 Edge Function 源码位于 `supabase/functions/`：
- `submit-assignment`：接收学生提交，校验权限与截止时间，写入数据库并调度 GitHub Actions。
- `grade-callback`：接收 GitHub Actions 评测结果，验证 HMAC-SHA256 签名并写分。
- `regrade`：教师发起复判，创建新 grading 行并记录审计日志。

#### 配置 Edge Functions Secrets：
```bash
# 共享 HMAC 回调密钥（随机生成 32 位字符串）
supabase secrets set GRADE_CALLBACK_SECRET="REDACTED-HMAC"

# GitHub Personal Access Token (需 repo / workflow 权限)
supabase secrets set GITHUB_TOKEN="<github-personal-access-token>"

# 绑定的 GitHub 仓库
supabase secrets set GITHUB_REPO="AmaneSuzuha000/SCIP-OJ"

# （可选）仅本地无 Actions 测试时开启 mock 评分
# supabase secrets set GRADE_RUNNER="mock"
```

#### 部署函数：
```bash
supabase functions deploy submit-assignment
supabase functions deploy grade-callback
supabase functions deploy regrade
```

---

### 3. 配置 GitHub Actions Secrets

进入 GitHub 仓库：**Settings -> Secrets and variables -> Actions**，配置以下 Repository Secrets：

| Secret 变量名 | 说明 | 示例 |
|---|---|---|
| `SUPABASE_URL` | Supabase 项目 URL | `https://xyzcompany.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase 服务端密钥 (service_role) | `eyJhbGciOi...` |
| `GRADE_CALLBACK_SECRET` | 与 Edge Functions 相同的 HMAC 密钥 | `REDACTED-HMAC` |
| `GRADE_CALLBACK_URL` | （可选）回调 URL 显式指定 | `https://xyzcompany.supabase.co/functions/v1/grade-callback` |

> [!IMPORTANT]
> `SUPABASE_SERVICE_ROLE_KEY` 与 `GRADE_CALLBACK_SECRET` 属于高危敏感信息，绝对不能出现在代码库或前端 JS 中。

---

### 4. 前端配置 (`site/config.js`)

复制示例配置文件：
```bash
cp site/config.example.js site/config.js
```
编辑 `site/config.js`：
```javascript
window.SCIP_OJ_CONFIG = {
  // 填写 Supabase 项目 URL 与公开 anon key（允许且必须在前端公开）
  SUPABASE_URL: 'https://<your-project-ref>.supabase.co',
  SUPABASE_ANON_KEY: 'eyJhbGciOi...<your-anon-key>',
  // 设为 false 表示真实对接服务端评测；设为 true 可在无后端时体验提交 UI
  MOCK_MODE: false,
};
```

> [!NOTE]
> `site/config.js` 已被 `.gitignore` 忽略，不会被提交至仓库。若缺少该文件，平台将优雅降级为**离线练习模式**，不影响既有的 L1 WASM 练习体验。

## 四、P001 端到端手动验收流程

### 步骤 1：学生端登录与练习
1. 打开 `site/index.html`，右上角应显示 **「登录 / 注册」** 按钮。
2. 点击按钮，在弹窗中选择 **「学生账号注册」**，输入学号（如 `20260001`）、姓名（如 `李同学`）、邮箱与密码并注册登录。
3. 登录成功后，页面顶栏显示：`👤 李同学 (20260001)`。
4. 在题单中点击 **P001 0-1背包问题**。
5. 作业元信息条展开：显示截止时间、及格线（90分）、计分规则（截止前最高分）。
6. 点击 **「⚡ L1 练习评分（浏览器 WASM）」**：
   - 浏览器在本地下载 WASM 并运行，数秒后在下方报告框中输出多实例算术平均分与分项扣分明细。

### 步骤 2：学生正式提交作业
1. 在代码框中输入正确的算法（如初始模板的动态规划，或使用 PySCIPOpt 建模）。
2. 点击 **「🚀 提交正式作业（服务端评测）」**。
3. 状态栏提示：`✅ 提交成功！公开编号 SUB-XXXXXXXX，已进入服务端评测队列。`
4. 下方 **「📜 我的提交记录」** 自动新增一行：
   - 编号：`SUB-XXXXXXXX`
   - 轮次：第 1 次
   - 评测状态：`⏳ 排队中` 或 `⚙️ 评测中`
5. GitHub Actions `grade-submission.yml` 自动被触发执行，runner 检出代码并运行 `judge/runner_l2.py`。
6. runner 完成评测后，通过 HMAC 签名回调 `grade-callback`。
7. 页面自动轮询（或点击「刷新提交记录」），评测状态更新为 `已完成`，显示得分（如 `90 分` 或 `100 分`）与 `✓ 通过`。
8. 点击「查看详情」，可展开查看服务端的 JSON 评测详细报告。

### 步骤 3：教师面板与成绩导出
1. 点击顶栏右上角或链接中的 **「教师面板」**（`site/teacher.html`）。
2. 登录教师账号（如 `teacher@scip-oj.local`）。
3. 课程选择下拉框选中：`SCIP2026A - 系统建模与优化 2026秋`。
4. 班级成绩表展示全班学生的最优分统计：
   - 学号：`20260001`
   - 姓名：`李同学`
   - 题目：`P001`
   - 最高分：`90` / `100`（绿色高亮通过）
   - 提交次数：`1`
5. 点击行末操作列的 **「查看」**：
   - 展开学生提交的代码原文与完整评测报告。
6. 点击 **「复判」** 按钮：
   - 输入复判原因（如 `教师抽查复判`），系统调用 `regrade` 函数并在 `grade_audits` 中写入审计记录，状态重置为 `queued` 并重新调度判题。
7. 点击 **「导出 CSV」**：
   - 浏览器自动下载含 UTF-8 BOM 的 CSV 成绩单文件（如 `scip-oj-gradebook-2026-10-22.csv`），在 Excel 中打开无乱码。

## 五、自动化烟测脚本

仓库提供了一键自动化烟测脚本，覆盖判题契约、系统异常隔离、HMAC 签名与 SQLite 替身数据库生命周期：

```bash
# 运行 Phase 1 自动化全链路自测
./platform/scripts/smoke_phase1.sh
```

输出全部显示 `✓ PASS` 且返回状态码 0 即表示核心逻辑验证完全正常。
