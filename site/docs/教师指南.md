# 教师与助教指南：SCIP-OJ 课程运营与评测证据台

本文档面向系统建模与优化课程的任课教师、助教与教务人员，介绍阶段 2 升级后的全套教学运营功能，涵盖课程邀请码、花名册管理、作业发布、成绩查阅、证据台核验、批量复判与成绩导出。

---

## 一、教师权限与进入控制台

1. **登录方式**：
   - 教师同样使用个人 **GitHub 账号**直接登录系统（无需专门注册独立密码）。
   - 确保教务管理员已在 Supabase 数据库 `enrollments` 表中将您的 GitHub 用户 ID 分配为对应课程的 `teacher` 或 `ta` 角色。
2. **进入控制台**：
   - 登录成功后，主站顶栏将显示紫色的 **「教师」** 身份标签，并在导航栏显现 **「教师面板」** 入口。
   - 访问地址：`https://<your-pages-url>/teacher.html`（或本地 `site/teacher.html`）。
   - 若普通学生账号访问教师面板，系统将自动显示权限拦截提示，禁止越权操作。

---

## 二、课程选择与邀请码管理

在教师控制台顶部，展示当前任课的班级与对应的选课邀请码：

1. **班级切换**：
   - 在「当前教学班级 / 课程」下拉框中选择您执教的课程（如 `SCIP2026A - 系统建模与优化 2026秋`）。
2. **学生选课邀请码**：
   - 系统为每门课程生成唯一的公开邀请码（例如 `SCIP2026-FALL`）。
   - 点击 **「复制邀请码」** 即可发送给班级群或写入选课通知，学生登录后输入该码即可一键加入教学班。
3. **轮换邀请码**：
   - 当选课周结束或需要防范非本班人员进入时，点击 **「轮换邀请码」** 按钮。
   - 教师可手动输入新码或由系统随机生成新短码，原有已选课学生不受影响。

---

## 三、花名册管理与学号自动对齐

为了避免传统 GitHub 账号与教务花名册脱节的问题，SCIP-OJ 提供了智能花名册对齐机制：

1. **导入花名册 (CSV)**：
   - 切换至 **「📋 花名册与导入」** 选项卡。
   - 点击「从文件导入 (.csv)」或在文本框中直接粘贴名单内容。
   - **格式要求**（支持任意逗号/分号/制表符分隔，允许带表头）：
     ```csv
     学号,真实姓名,可选GitHub用户名
     20260001,李同学,litongxue
     20260002,王同学,wangtongxue
     20260003,张同学,
     ```
   - 点击「确认导入名单」，系统自动录入 `roster_pending` 表。
2. **双向自动对齐规则**：
   - 学生无论使用何种 GitHub 账号登录，在首次提交前，系统弹窗强制要求填写其**学号**与**真实姓名**。
   - 学生填入的学号一旦与花名册一致，系统触发器自动将状态标记为 `✓ 已对齐入库`，后续所有评测成绩均自动归属于该学号学生。
3. **查阅待对齐明细**：
   - 面板下方实时汇总展示两类学生：
     - **已对齐入库**：已通过 GitHub 登录并成功核验身份的学生；
     - **待绑定登录**：在册但尚未登录认领账号的学生名单，便于助教点名催促。

## 四、作业发布与调整（免改代码）

无需改动代码仓库，教师可直接在控制台向班级发布或调整作业：

1. **发布作业**：
   - 切换至 **「🚀 发布 / 调整作业」** 选项卡。
   - **选择题目 (problem_id)**：系统自动扫描 `problems/` 题库（如 `P001` - 0-1背包问题，`P002` - 指派问题），亦可手动输入新扩展题目。
   - **截止时间 (due_at)**：使用时间选择器精确设置截止时刻；超过截止时间的提交系统将自动打上红色「迟交」标记。
   - **及格线 (pass_score)**：默认为 90 分。
   - **测试实例数 (n_instances)**：默认为 3（服务端评测将生成 3 组独立随机算例并取算术平均分）。
   - **计分策略 (score_policy)**：
     - `highest_before_due`（默认）：截止时间前的历史最高分，截止后刷分不冲抵更早的及格分。
     - `latest`：以截止前的最新一次有效提交分数为准。
     - `highest`：全局最高分。
   - 点击「发布 / 保存作业配置」，立即对学生端生效。
2. **快捷修改**：
   - 下方表格列出当前课程已开放的所有作业。
   - 点击任意行的「填入表单修改」，表单自动回显，教师可一键延长截止时间或调整及格线。

## 五、班级成绩表与评测证据台

切换至 **「📊 班级成绩与证据台」** 选项卡，可进行全面的成绩核算与证据审查：

1. **多维筛选与搜索**：
   - 支持按特定题目筛选（如仅看 `P001`）；
   - 支持按学号、学生姓名模糊搜索。
2. **成绩视图明细**：
   - 表格包含：学号、真实姓名、题目编号、最优成绩（绿色通过/红色未过）、迟交标记（迟交/正常）、提交轮次、最后提交时间。
3. **评测证据台 (Evidence Station)**：
   - 点击任意行的 **「查看证据」**，下方展开完整的证据抽查台：
   - **评测状态时间流水线**：
     - `学生提交 (SUB-XXXXXXXX)` → `进入评测队列 (Runner ID)` → `评测执行完毕` → `权威判定 (HMAC 验签回调入库)`。
   - **只读源码审查框**：原样展示该学生提交给 GitHub Actions runner 执行的真实 Python 代码，代码哈希防篡改。
   - **结构化评测报告 (report_json)**：查看多实例得分分解、扣分明细、运行耗时与求解器日志。

## 六、复判机制（单条、批量与整题一键重判）

所有复判操作均会由系统记录至 `grade_audits` 审计日志表，包含操作人、旧分数、修改时间与复判原因，确保教学评测公正透明：

1. **单条复判**：
   - 在证据台点击「🔄 发起单条复判」，输入复判说明后，该提交重新进入服务端评测流水线。
2. **批量复判**：
   - 在成绩表勾选多个学生的提交行，点击顶部工具栏 **「批量复判选中项」**。
   - 系统弹出进度提示条（如 `正在调度批量复判 (3/10)…`），支持并发批量调度。
3. **整题一键重判**：
   - 当题目测例更新、参考解答调整或评测脚本优化后，选择对应题目，点击 **「整题一键重判」**。
   - 系统将自动遍历该课程该题目下所有学生的提交，一键批量重测并刷新最优分。

---

## 七、成绩导出 (CSV)

- 点击工具栏 **「导出成绩 CSV」**。
- 系统将在本地浏览器直接组装含 **UTF-8 BOM** 的标准化 CSV 文件（如 `scip-oj-gradebook-2026-10-22.csv`）。
- **字段包括**：学号、姓名、题目、最高分、是否通过、迟交状态、提交轮次、最后提交时间。
- 双击即可在 Microsoft Excel、WPS 或 Numbers 中正常打开，绝无中文乱码。
