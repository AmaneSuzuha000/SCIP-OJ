# SCIP-OJ 平台阶段 3：前后端全面打磨与交付指南

> 本文档记录平台在阶段 3 完成的前后端全面打磨、视觉与信息架构升级、安全加固及工程化重构细节。

---

## 1. 架构目标与产品硬边界

1. **正式成绩唯一性**：正式成绩**必须且仅由**服务端评测引擎（GitHub Actions + PySCIPOpt）生成并入库 Postgres。浏览器端 L1 / WASM 仅作练习自测，其评分存储于 `localStorage`（键 `scip-oj-practice:<id>`），绝不写入正式成绩中心。
2. **纯粹 GitHub OAuth 登录**：仅保留 GitHub OAuth 认证。学生无需开 PR、无需 Fork 仓库、无需查看 Actions 细节，一切操作在 OJ 前端完成。
3. **安全与密钥隔离**：
   - 严禁向前端 `site/` 注入任何 `service_role`、GitHub PAT、HMAC 或自定义密钥；
   - Edge Functions 密钥回退链保持：优先 `Deno.env`，缺失时查询 `public.platform_secrets`（RLS 保护，仅 `service_role` 可读）；
   - 评测系统故障（`system_error`）与学生 0 分严格隔离。

## 2. 前端打磨清单（Part A）

### 2.1 视觉与信息架构（Visual & Information Architecture）
- **现代化设计系统 (`site/style.css`)**：
  - 采用 GitHub Dark / LeetCode 风格深度暗色专业配色规范（`--bg-base: #0d1117`, `--bg-surface: #161b22`, `--border-default: #30363d`）；
  - 规范字体层级（sans-serif 系统字体与 JetBrains/SF Mono 编程等宽字体结合）；
  - 标准化按钮层级：L1 练习自测（绿色 `btn-green`）、正式提交（电光蓝 `btn-blue`）、次要操作（中性色 `btn-secondary`）、复判与警告（琥珀色 `btn-warning`）；
  - 现代化卡片、表格、表单输入框、聚焦光晕（Focus Ring）、徽章状态（queued, running, done, system_error, late, normal, matched, pending）；
  - 引入轻量级非阻塞 Toast 通知系统（代替原生 `alert()`）。

### 2.2 学生端体验升级 (`index.html` + `app.js`)
- **题单大厅**：
  - 题目卡片网格化展示，直观呈现题目编号、难度等级、算法知识点标签；
  - 顶部动态班级横幅：显示当前已加入教学班级名称及状态，提供一键换选课入口；
  - 实时题目搜索与过滤（支持题号、名称、难度、标签）。
- **题目工作台**：
  - 顶部元信息栏（Meta Bar）：截止时间（含迟交预警）、及格线（默认 90 分）、计分规则、多实例测例数量；
  - 题目描述以结构化 Markdown 呈现（表格、公式、代码高亮）；
  - 算法代码编辑器：支持「复制代码」与「重置为模板」；
  - L1 练习自测：Pyodide WASM 浏览器本地秒级真跑，实时输出格式化终端日志；
  - 正式提交：校验学号门禁与选课门禁，调度服务端 PySCIPOpt 评测，生成短码 `SUB-XXXXXXXX`；
  - 提交历史记录：智能轮询评测状态（排队中、评测中、已完成、系统故障），支持点击查看结构化评测证据详情；
  - 脱敏排行榜：支持按当前题目查看班级最高分排名，学生学号隐私脱敏（`2026****01`）。

### 2.3 教师控制台体验升级 (`teacher.html` + `teacher.js`)
- **权限安全拦截**：非教师或助教角色访问时，展示友好且专业的拦截卡片，提供明确的权限指引并可一键返回学生大厅；
- **班级与邀请码**：快速切换授课班级，一键复制邀请码或自定义轮换新邀请码；
- **班级成绩与证据台**：
  - 成绩表格支持全选/多选复选框、按题目筛选、按学号或姓名实时检索；
  - 单条提交证据台：侧滑展示学生提交源码（带复制）、`report_json` 结构化报告、自动化评测生命周期时间线（学生提交 → 进入队列 → Actions 评测中 → HMAC 验签入库）；
  - 支持单条复判、多选批量复判、整题一键重判（写入 `grade_audits` 审计日志）；
  - 成绩单 CSV 导出：自动包含 `\uFEFF` UTF-8 BOM 前缀，Excel 导出不乱码。
- **花名册与 CSV 导入**：
  - 班级对齐统计徽章（预置总数、已对齐、待绑定）；
  - 支持文本框粘贴与本地 `.csv` 文件载入，自动解析表头与多分隔符；
  - 学生花名册对齐明细表，直观显示每位学生的绑定状态。
- **作业发布与调整**：
  - 教师可视化表单快速配置各题考核要求（截止时间、及格线、测试实例数、计分策略）；
  - 已发布作业表格列表，支持「填入表单修改」一键回填编辑。

## 3. 后端打磨与工程化（Part B）

### 3.1 Edge Functions 模块化与 `_shared/` 统一
创建了共享模块目录 `supabase/functions/_shared/`：
- `cors.ts`：统一 CORS 响应头、`handleCors(req)` 预检处理、`jsonResponse(...)` 与 `errorResponse(...)`；
- `secrets.ts`：`getPlatformSecret(...)` 密钥解析助手（`Deno.env` -> `platform_secrets`）；
- `auth.ts`：`getAuthenticatedUser(...)` 与 `isTeacherOrAdmin(...)` 角色与权限校验；
- `github.ts`：`dispatchGitHubWorkflow(...)` 安全调度 GitHub Actions（脱敏日志，不泄露 Token）。

重构并统一以下 6 个核心端点：
1. `submit-assignment`：OPTIONS 预检、选课与学号门禁、SHA-256 哈希、迟交打标、Actions 触发异常隔离为 `system_error`（不打 0 分）；
2. `grade-callback`：支持 OPTIONS 预检，修复 HMAC 签名验证，幂等处理重复回调；
3. `regrade`：教师鉴权、创建 queued 记录、记录 `grade_audits` 审计日志；
4. `regrade-batch`：支持多 ID 批量复判与整题一键重判（限制单次最大 50 条）；
5. `join-course`：邀请码选课、有效期与使用上限校验、双向关联 `roster_pending`；
6. `publish-assignment`：参数严格校验（分值 0-100、实例 1-20、计分策略枚举）、`assignments` 幂等 upsert。

### 3.2 数据库 Schema、安全与索引 (`005_polish_security_and_indexes.sql`)
- **权限提权防御**：在 `profiles` 表增加触发器 `trg_prevent_profile_role_escalation`，拦截普通学生通过 UPDATE 自行将 role 修改为 `teacher` 或 `admin`；
- **核心业务索引**：
  - `idx_roster_pending_student_no_lookup`（花名册不区分大小写匹配加速）；
  - `idx_course_invites_code_ci`（邀请码快速检索）；
  - `idx_gradings_submission_status`（评测状态查询加速）；
  - `idx_submissions_assignment_created`（作业提交流水排序索引）；
  - `idx_grade_audits_grading` 与 `idx_grade_audits_actor`（审计日志索引）；
- **RPC 增强**：`join_course_by_code` 增加空值校验、大小写清洗与花名册对齐保障；
- **权限授予**：显式授权 `anon` 与 `authenticated` 访问必要表与视图（受 RLS 保护）。

## 6. 006 增量安全迁移（本次 UI/交互评审新增）

迁移脚本：`supabase/migrations/006_security_hardening_and_leaderboard.sql`

- **成绩簿防越权**：`course_gradebook` 视图撤销 `authenticated` 直接 SELECT，改由
  `get_teacher_gradebook(course_id)` RPC 校验 `is_teacher_of()` 后返回；此前任何登录用户
  都能读取全站学生学号、姓名与成绩。
- **排行榜脱敏**：新增 `get_course_leaderboard(course_id, problem_id)` RPC，仅本课程师生可读，
  学号在数据库侧脱敏（`LEFT(...,4) || '****' || RIGHT(...,2)`），浏览器不再收到完整学号。
- **邀请码防枚举**：`courses` 改为列级授权（仅 `id/name/code/created_at`），邀请码通过
  `get_course_invite_code()` 只对课程教师返回；`join_course_by_code` 不再把公开的
  `courses.code` 当作邀请码。
- **角色一致性**：`enrollments.role` 约束扩展为 `student/teacher/ta/admin`（Edge Function 早已写入 `ta`）；
  `is_teacher_of()` 同步识别 `ta/admin`；`handle_new_user()` 固定写入 `student`，不再信任客户端 metadata。
- **密钥回退表**：创建文档中已引用但此前从未建立的 `public.platform_secrets`（RLS 开启、仅 `service_role` 可读写）。
- **重复选课计数**：`join_course_by_code` 仅在真正新增选课时递增 `course_invites.uses_count`。
- **评分确定性**：`course_gradebook` 的 `ranked_scores` 增加 `gradings.created_at DESC` 作为同分/复判的
  最终排序键，避免复判后展示旧分数。
- **提交写入收紧**：撤销 `authenticated` 对 `submissions` 的 INSERT 权限与对应 RLS 策略，正式提交只能经由
  `submit-assignment` Edge Function（服务端校验选课、学号、截止时间与体积）。

应用命令（需先 `supabase link --project-ref <ref>`）：

```bash
supabase db push
```
